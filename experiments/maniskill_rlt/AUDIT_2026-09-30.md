## Continuation: Action Sensitivity

The evaluator now tests zero arm commands (gripper preserved) and reversal of only the executed action prefix. Reversing a full chunk at a short horizon would expose future commands, so a regression test protects that boundary. These are input perturbations, not counterfactual physics rollouts. New seed batches and 250/1000-update comparisons are queued externally; no control-success claim follows from these metrics.

The focused CPU model/data suite passes 194 tests, with one optional skip and the known baseline VideoMetadata test excluded. Default online losses remain unchanged.

### Prepare a better-matched online pilot

The opt-in `RLT_SMOKE_PROFILE=matched` adds `pilot/rlt_matched.yaml` to both control and world configurations. Both use original FSDP parameters, batch 32/microbatch 8, 512 BC-only warmup updates and the same BC/Q ramp; each outer iteration runs at most 64 learner updates. Evaluation uses four fixed environments with video. The old short smoke stays unchanged. The launcher shares the GPU 2 lease with other project jobs and still refuses a busy GPU.

Set `RLINF_VENV`, `RLT_STAGE1_ACTOR` to step 2000 and `RLT_WORLD_CHECKPOINT` to a sidecar with the same frozen-feature contract, as described in the README. Then validate both arms without allocating a GPU:

```bash
export RLT_SMOKE_PROFILE=matched RLT_SMOKE_STEPS=20
export RLT_EPISODE_STEPS=500 RLT_SAVE_INTERVAL=5 RLT_VAL_INTERVAL=5
bash run_rlt_stage2_smoke_gpu2.sh --check
bash run_rlt_stage2_smoke_gpu2.sh --world --check
```

Both preflights and the configuration-parity regression pass; the latest model/data suite has 195 passed, one optional skip and one known baseline exclusion. This profile has not run end-to-end. Longer warmup does not prove reference imitation; inspect BC/action-deviation and rollout behavior before promoting it. Four repeated fixed initial states are not twenty independent evaluation seeds. To execute after exclusive GPU availability, omit `--check`, run the no-world arm first, and stop if it fails.

## Implementation

`rlt_latent_world.py` masks invalid future labels and padded actions before LayerNorm, nonlinear losses and BC. This prevents finite final losses from hiding NaN gradients; invalid valid-position data is not globally sanitized. New `condition_on_actions=False` zeros action inputs without changing parameter counts; its default is True.

`toolkits/rlt/ablate_action_input.py` runs direct, residual and action-free residual models with one fixed split, three initializations and 1000 updates each. Validation selects checkpoints. The disjoint development-test episodes have been inspected before and are not a sealed final test.
