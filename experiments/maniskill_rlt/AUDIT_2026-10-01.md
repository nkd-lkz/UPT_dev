# 2026-10-01: Delayed Feedback and Stale Reset Protection

The CPU response diagnostic now separates prediction issuance from outcome completion. `ResponseHistory.issue(command)` returns a unique ticket, prediction and excitation support; `complete(ticket, outcome)` compares the result with the prediction stored before execution, then writes evidence. Completion is ordered, duplicate/unknown tickets fail, and `reset()` invalidates pending tickets. Pending outcomes never enter prediction.

A new `stale_reset_guard=True` tags predictions by estimator generation. After a reset, delayed predictions from the old generation can still write completed observations but cannot repeatedly reset the new estimator. This is diagnostic-only: production memory, actor inputs and training defaults remain unchanged.

Six seeds × three conditions × six retention methods × delays 0/2/5 = 324 synthetic streams (not robot episodes). With five-step delay, unguarded adaptive reset fires three times per shifted stream; the guard reduces this to once. Across six seeds, gain-rise late MSE changes from 0.00000818 to 0.00000502. Stationary streams have no false resets. Early adaptation remains delayed: the guard cannot recover feedback that has not arrived.

Run `python -m toolkits.rlt.probe_response_shift --output NEW_DIRECTORY --feedback-delay 5` to compare all six methods. Artifacts: `$RLT_STORAGE/research/zeva_guard_delay{0,2,5}_20261001/results.json`. CPU model/memory regression: 97 passed and one optional skip. Real contact, asynchronous robot transport, task success and transfer remain untested.
