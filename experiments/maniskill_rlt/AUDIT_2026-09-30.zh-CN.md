# 2026-09-30：有限动作选择与连续修正对照

本轮补齐同幅度连续 residual，使“限制探索范围”与“离散选择”的贡献可以分开检验。[完整报告](https://github.com/nkd-lkz/physical-self-evolution/blob/main/research/three-branch-audit-2026-09-30.md)提供曲线、来源和证据限制。

## 新增路径

`RLTBoundedResidualPolicy` 沿用 RLT 的 actor/critic，执行 `clip(reference + radius * tanh(raw_arm), -1, 1)`。夹爪沿用参考；确定性初始化等于已裁剪 reference。radius 写入 checkpoint 合同；entropy 权重必须为零，因为变换前 log probability 不是完整动作分布密度。

`bounded_residual` 与 `atomic_decision` 互斥，默认都不改变 baseline。新增 `RLT_ATOMIC_PROFILE=residual`，使用与 atomic pilot 相同环境、batch、更新及评估预算。两个方法具有相同每分量幅度边界，但连续 actor 可以同时修改多个关节与时间步，表达空间并不相同。

## 小实验告诉了什么

实际 RLT loss 在同一批 2048 条合成 transition 上训练，另用 256 个 context 评估。每条件三初始化、1000 critic 更新：

- 只含候选动作数据：离散最终 reward 为 0，连续约 −8.03 至 −8.25。
- 加入一半连续动作数据：结果未明显改善。
- critic 先学习 300 更新，actor LR 降至 1e-4：连续约 −3.57 至 −5.34，仍有退化。

0 是合成解析任务的最优 reward，不是机器人成功率。连续 actor 通过解析监督拟合测试，问题指向 learned critic 的梯度／数据支持和优化条件；不能用这个偏向有限候选的任务证明离散 actor 普遍更优。后两组是探索性追加，不是预注册确认实验。

CPU 回归 **204 passed、1 skipped、1 deselected**；排除项是 baseline 也失败的 VideoMetadata 依赖问题。atomic 小模型在物理 GPU 2 完成单 rank fp32 FSDP 20 次更新和恢复一致性；这不是完整 VLA／ManiSkill online smoke。自动队列继续保留空闲门槛，不会挤占 GPU 0/1。

## 如何运行对照

在本分支根目录、已有环境中执行；输出目录必须不存在：

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 python -m pytest \
  tests/unit_tests/test_atomic_decision.py tests/unit_tests/test_models.py \
  tests/unit_tests/test_data.py \
  -k 'not test_vlm_trend_batch_video_metadata_stays_nested_per_sample' -q
CUDA_VISIBLE_DEVICES='' python -m toolkits.rlt.compare_residual \
  --output "$RLT_STORAGE/research/jev_residual_new" --steps 1000 \
  --data-mode mixed --actor-start 300 --actor-lr 0.0001
RLT_ATOMIC_PROFILE=residual bash run_rlt_atomic_gpu2.sh --check
```

最后一条不训练。只有显式 `--run` 且现有 GPU 2 检查通过才启动完整 pilot。下一步需要真实在线采集、相同调参预算、固定初态评估和成本核算。
